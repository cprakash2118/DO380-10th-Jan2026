LDAP Group Synchronization:-
#### OpenShift can connect to an external LDAP directory server (MIcrosoft AD, Open LDAP, RedHat IDM etc) to automatically import and keep users/groups memberships synchronized.

#### Why LDAP group sync needed ?
  - When Org already manages groups in LDAP/AD, We don't want to recreate and manage locally in OpenShift.
  - Synchronization ensures that RBAC group memberships in OpenShift reflect same as LDAP/AD.
  
##### HOw it workds (Backend):-
Step-1-) LDAP server - Maintains users, groups and relationships (Who belongs to which group).

Step-2-) OpenShift OAuth IdP - Handles users authentication against LDAP/AD.

Step-3-) Group Sync COntroller - Connect to LDAP server, reads groups and updates OpenShift's internal Group
object accordingly.

Step-4-) Automation (via cronjobs) - Keeps synchronization recurring so OpenShift group always stay up to date.


#### Required COmponents - TO enable synchronization, OpenShift needs:-
- Configuration file (Telling it how to connect to LDAP - [CR - LDAPSyncConfig]
- Service Account with permission to perform the sync.
- Cluster role + Role binding - SO the serviceAccount can create/update groups.
- ConfigMap and Secret to store connection info securely (Like password and certificate)
- Conrjobs to schedule recurring sync.

#### Group and lookup rules.
- It help you to describe how to locate groups in LDAP.
  - groupUIDAttribute: Unique ID of the group (Like dn)
  - groupNameAttribute: Field used as OpenShift group name (cn)
  - groupMembershipAttribute: This field lists the members (member).
  
#### Define user lookup rules:-
 How to locate the user.
 BaseDN - Eg:- ou=users,dc=ocp4,dc=example,dc=com
 Filter - objectClass=preson 
  - userUIDAttribute: Unique ID of the user (Like dn)
  - userNameAttribute: Field used as OpenShift user name (cn)
